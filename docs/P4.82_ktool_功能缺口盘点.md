## 一、现在有什么

### 用户态 `ktool`（18 条命令）

| 命令 | 作用 | 限制 |
|---|---|---|
| `target` | 按 model/kernel 串匹配适配表 | **表里只有 GT-I9500 一条** |
| `dump` / `read` | 读内核内存并 hex 打印 | len ≤ 4096，内部按 64B 分块 |
| `find` | 遍历 task 链表找自己 | 每次命令都要重跑一遍 |
| `root` / `pwn` | 改 cred（+ permissive） | 依赖 1805 读写原语 |
| `boot` | `lkmauth_bootmode=2` + permissive + `insmod` | 三段拼装，模块路径写死参数 |
| `gate` | 改写 `task+0x2EC` 让 `/dev/ktool` 门禁放行 | 只对 uid0 进程有效 |
| `setuid` / `setids` / `snr` / `caps` | 改自己的 uid/gid/caps | 只能改自己 |
| `w32` | 写 4 字节（读-改-写 8 字节） | 只支持 32 位 |
| `sh` / `shfull` / `rawexec` / `x` | 以 root 执行 | — |
| `ls` / `cat` / `cp` | 以 root 读文件 | — |
| `who` / `idel` | 身份显示 / watchdog 观测 | — |

底层 `kread` / `kwrite`：
- 单次 **len ≤ 2000**，且必须是 **8 的倍数**；
- 实现完全绑定 **CVE-2015-1805**（`writev` 越界 + `madvise` 竞态 + `sendmmsg` 喷雾 + canary 自校验）；
- 每次调用最多 300 次 try，成功率约 1/3；
- `kwrite` 用 `kwrite_verify`（写后读回比对）。

### 内核模块 `ktool_mod.ko`（14 条命令）

`root` / `restore`、`wfind` / `wfind16` / `wdump`、`ksym`、`kread`、`waiter`、
`bugtest` / `warntest`、`avcflush`、`ish`、`ctx`、`fixlbl`、`lbldbg`。
除 `root`/`restore` 外，其余全部要求 uid0（`ktool_is_uid0()` 门禁）。

## 二、缺口（按"换机能不能用"排序）

### P0：阻断级 —— 换机型直接失效

| # | 缺口 | 后果 |
|---|---|---|
| 1 | **读原语写死**：`kread`/`kwrite` 内部就是 1805 的实现，没有后端抽象 | S5 上 1805 已修（5 参）⇒ **整个工具不可用**，不是慢，是跑不起来 |
| 2 | **适配表只有 1 条**（GT-I9500），`[A]` 类 5 个地址（`init_task`/`modprobe_path`/`permissive_map`/`exec_br`/`lkmauth_bootmode`）全部来自 S4 镜像 | 换机需要手工重推 5 个地址并改表，没有任何自动推导 |
| 3 | **模块按 S4 的 `task_struct` 布局编译**（cred@0x2FC 等），且加载需要 `insmod` 权限 | S5/S6 若 KNOX/TIMA 收紧，模块路直接断；换机要重编 + 重测偏移 |
| 4 | **符号解析只在模块里**（`ksym`） | 没有模块的机器上，"函数名→地址"没有替代路径 |

### P1：能力级 —— 限制能做什么

| # | 缺口 | 影响 |
|---|---|---|
| 5 | 单次读写 ≤2000B 且 8 字节对齐；`dump` ≤4096；**没有二进制落盘** | 做内存结构转储/扫描时极难用，只能 hex 刷屏 |
| 6 | **没有"内核内存搜索"**（`wfind` 是模块侧、且是写向的） | 找 cred / 找 task / 找符号只能靠已知地址，不能"喷图案再找" |
| 7 | **没有自清理**：cred 改了不可逆；`do_ctx` 只能往前切；`restore` 只在模块 | 实验后无法回到干净态，只能重启 |
| 8 | 写操作无回滚：`kwrite_verify` 失败时目标已被改了一半 | 半改状态比不改更危险 |

### P2：体验/健壮

| # | 缺口 | 影响 |
|---|---|---|
| 9 | 竞态无自适应退避；一次失败会跑满 300 try | 烧 CPU，并在内核态留下 `kill -9` 杀不掉的忙等线程（P4.50 踩过） |
| 10 | 每条命令都重新 `find_self()`（一次链表遍历 + 竞态） | 无法"一次会话多命令"，脚本化成本高 |
| 11 | `panic_on_oops=1` 下没有"跑前记录 / 跑后取现场"的自动化 | 崩一次就重启，现场靠人肉 dmesg |

### 模块侧（若继续走模块路线）

- `waiter` 假设 plist 布局，rbtree（3.14+）机器不可用；
- 缺"隐藏/自保护"，重启即暴露（实验够用，实用不够）；
- `ktool_is_uid0` 用的是实测偏移，换内核必须重新标定（曾因此连拒 8 次）。

## 三、最该补的三件事（按对最终目标的价值）

### 1. 把读原语抽成后端接口（P0-1）

```c
struct krw_backend {
    const char *name;
    int (*read)(unsigned long addr, void *buf, int len);
    int (*write)(unsigned long addr, const void *buf, int len);
    int (*probe)(void);          /* 自检：读一个已知值 */
};
```

现有 1805 实现变成 `backend_iovyroot`；换机只需再写一个 `backend_xxx`。
`do_root` / `find_self` / `dump` 全部走这层，不再直接调 1805 的细节。

**收益**：S5/S6 只要找到任意读，工具立刻可用，不用改一行业务逻辑。

### 2. 目标表 + 离线符号表（P0-2、P0-4）

- `targets.h` 的 `[A]` 类地址改成"可由镜像自动推导"：给一份 `vmlinux`，
  用我们已有的反汇编流程算出 `init_task` / `permissive_map` / `modprobe_path`；
- 新增 `ktool sym <name>`，从本地 `System.map` 格式文件查地址（不依赖模块）；
- `target` 已支持按 `/proc/version` 匹配，补条目即可。

**收益**：换机从"半天手工"变成"跑一遍脚本 + 生成一张表"。

### 3. 大块 IO + 内存搜索（P1-5、P1-6）

- `kread_file <addr> <len> <out>` / `kwrite_file <addr> <in>`：
  分块（≤2000、8 字节对齐）+ 自动补齐 + 逐块校验；
- `scan <start> <len> <pattern>`：读一段内存做模式匹配，命中即打印地址。

**收益**：从"手搓单点读写"变成"能扫结构、能落盘分析"，这是做通用链的必要工具形态。

---

## 四、结论

- **S4 上够用**：18 条命令 + 模块 14 条，覆盖提权、permissive、insmod、调试。
- **S4 之外不可用**：三处硬绑定（1805、适配表、模块布局）都在 P0。
- 想让它成为"跨机型工具"，**必须先做后端抽象**，否则每次换机都是重写而不是移植。

## 五、复审（P4.83 / P4.84 落地之后）

用户态命令从 18 条涨到 35 条（`backend boot caps cat cp dump find flush gate idel
kread_file kwrite_file ls patch permissive pwn rawexec read restore root scan scan4
selftest setids setuid sh shfull showcred snr stat sym target unpatch unperm w32 who x`）。

### 已经补掉的

| 原缺口 | 现状 |
|---|---|
| P0-1 读原语写死 | 有 `krw_backend` 接口，业务层只走 `kread/kwrite`；**但实现仍只有 1805 一个** |
| P0-4 符号只在模块 | `sym`：离线 map，`name→addr`、`addr→sym+off`、通配；不再需要 insmod |
| P1-5 无二进制落盘 | `kread_file` / `kwrite_file`，任意长度、尾块 RMW、逐块校验 |
| P1-6 无内存搜索 | `scan`（字节串）+ `scan4`（32 位值/范围，值可反查符号） |
| 工具链 | 本机无 zig，`build.sh` 改 GNU 静态；443KB |

### 仍然缺的（按会不会卡住最终目标排）

**A. 阻断级——换机直接跑不起来**

1. **只有 1805 一个读原语**。S5 的 1805 已修（P4.78），S6 未验；这两台上 ktool
   一条读写命令都用不了。这不是"缺功能"，是"缺入场券"。
2. **targets.h 只有 S4 一条**，且 6 个 [A] 地址里只有 `init_task`/`modprobe_path`
   是符号；`permissive_map`/`avc_slots`/`exec_br`/`lkmauth_bootmode` 是结构体内
   地址或指令地址，`sym` 查不到，仍要反汇编推。
3. **模块路绑死 S4 布局**（`cred@0x2FC` 等）+ 需要 insmod 权限，S5/S6 若 KNOX/TIMA
   收紧就直接断，且换机要重编重标。

**B. 链路级——能跑，但跑不完整**

4. ~~**写不是事务**~~（P4.86/P4.87/P4.88 已解决）：`kwrite_txn` = 快照 → undo 日志 →
   8 字节块逐块写 → 失败回滚；另有 `ktool undo` 从日志还原。
   **三次修正**：P4.87 发现写原语逐条 iovec 落地、`kwrite` 永远返回 0
   （8B 5/5、16B 1/5、32B 0/5、48B 0/5、72B 1/5）→ 必须切 8 字节块；
   P4.88 又发现①同进程连写多块时第一块之后系统性失败，块间必须穿插一次读；
   ②写完立刻读回会读到污染数据（读回说 euid=0 而 geteuid()=2000），
   `drain()` 只能修好一部分 → **promote/unroot 的验证全部改成内核视角
   （getuid/capget）+ 6 次重试**。实测 6/6 promote→unroot 往返。
5. ~~**改 cred 不可逆**~~（P4.86/P4.88 已解决）：`promote` 前存 72 字节 cred 快照
   （不含 usage），`unroot` 带 uid/euid/gid/egid/caps 全量校验还原；
   实测 uid 2000→0→2000。**只在本会话内有效**（进程一退 cred 即释放）。
6. ~~**没有会话**~~（P4.85 已解决）：`ktool repl` 一个进程跑多条命令，
   `promote` 提权后持续有效，`find_self` 带 comm 校验缓存，
   另有 `history`/`!N` 回放、`kread_file -r` 续传；
   一次性 2.2~7.4s/条 → 会话 0.45s/条。
7. ~~**竞态无自适应退避**~~（P4.86 已解决）：连续失败 3 次后 +200µs/次、封顶 2ms，
   成功清零；`bench` 可量化（avg tries 1.7~3.0，0.4ms/读）。
8. ~~`restore` 名不副实 / `--stock` 多余~~（P4.88 已解决）：改名 `enforce`
   （`unperm`/`restore` 留别名，开机脚本还在用），删 `--stock`（它等于
   `unpatch + enforce`，而 unpatch 本就是独立命令），`flush` 的审计风暴告警
   写进命令本身（依据 P4.12 的 RST_STAT=0x200 实证）。
9. **模块路仍按 S4 布局编译**：其实已经是 `targets.h` 表驱动（只剩
   `ktool_is_uid0` 一个硬编码 0x2FC）。P4.88 评估**不值得单独解耦**——
   换机的真门槛是 insmod 权限而不是布局，且偏移可用现有工具在设备上标定。

**C. 分析效率——能做，但慢**

9. ~~**吞吐 12KB/s**~~（P4.86 已证伪并修好）：实测 bulk 读 ~4.8MB/s，
   原来的 12KB/s 把"每条命令 2s 启动"算进吞吐了。真正的瓶颈是空洞——
   64KB 空洞扫描 14.2s → 60ms（24 次探测 + 300 次确认读 + 步长放大）。
   页表级跳过经评估不做（代价/收益不划算）。
10. ~~**只有单层等值与区间**~~（P4.84/P4.85/P4.86 已补）：`scan4` 找"谁存着 X"，
    `walk <sym> <off>...` 顺着指针走下去，`findcred [-u uid]` 按形状找对象
    （有噪声，适合小范围 + uid 过滤），`fld <off:type>` 一行读结构，
    `dis <addr>` 保守反汇编。仍缺真正的多条件 DSL。
11. ~~**read 卡 4096 / 无超时 / 无续传**~~（P4.87 已解决）：`-t <秒>` 全局预算、
    `read` 放到 16MB、`kread_file -r` 续传。
12. S5 的 kallsyms 还没提出来（`s5_vmlinux.bin` 不是 ELF），`sym` 在 S5 上无表可查。

**D. 健壮性（本轮顺手修的）**

11. `dump`/`read` 的 len 不是 8 的倍数时直接失败（`kread: bad len 10`）——
    已改为走 `kread_buf`，任意长度可读。
12. `find` / `selftest` 缺参数会拿 `argv[2]`=NULL 去 `strlen`/`strtoul`（崩溃）——
    已补 usage 检查。
13. 仍缺：`kread_file --resume`、`read` 的 4096 上限、命令行可配超时
    （`g_io_deadline` 只有 `do_root_inner` 里硬编码的 15s）。
