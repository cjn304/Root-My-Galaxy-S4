## 4. P2.3 漏洞路径触发（trigger.c）

### 构造拓扑（三次迭代后定型）

```
A: LOCK_PI(u3)                        → A 持有 u3
A: WAIT_REQUEUE_PI(u1, 0, u2) 1.5s超时 → A 睡在 u1，栈上 rt_waiter 登记
B: LOCK_PI(u2)                        → B 持有 u2
B: LOCK_PI(u3)                        → B 阻塞（pi_blocked_on 挂在 u3）
C: CMP_REQUEUE_PI(u1→u2, nr=1, expect=0)
```

### 两次失败与根因（记录备查）

1. 第一次：B 先启动，抢在 A 之前拿到 u3 → 拓扑不成立。
2. 第二次：`tv_nsec += 2e9` 只归一化一次 → timespec 非法（tv_nsec≥1e9）→ hrtimer 提前到期，A 在 C 到达前退出。修正为 while 归一化。

### 命中结果

```
[A] LOCK_PI(u3) = 0, u3=0x00004f4d
[B] LOCK_PI(u2) = 0, u2=0x00004f4e
[C] CMP_REQUEUE_PI(u1->u2) = -1 (errno=35 EDEADLK)
[A] WAIT_REQUEUE_PI = -1 (errno=110 ETIMEDOUT)
[A] after: u2=0x80004f4e (WAITERS 位被原子尝试置位)
```

**errno=35 即漏洞路径执行证明：**
- u2 字值 = B 的 tid(0x4f4e) ≠ A 的 tid → `futex_lock_pi_atomic` 的自锁短路（L~830）不会命中
- EDEADLK 只能来自 `task_blocks_on_rt_mutex` 的链走（`rt_mutex_adjust_prio_chain`: `owner(u3)==top_task(A)`）
- 该返回值经 `start_proxy_lock` 的 `if (ret && !rt_mutex_owner(lock)) ret=0;`（owner=B 非空）→ `remove_waiter(lock, waiter)` 以 **current=C** 执行 ← CVE 本体

### 事后状态

- A 于 1.5s 超时正常返回；B 在 A 退出后取得 u3
- **`A->pi_blocked_on` 遗留为悬空指针（指向 A 已退栈的 rt_waiter）**——利用原语就绪
- `remove_waiter` 内 `WARN_ON(!plist_node_empty(&waiter->pi_list_entry))` 未触发（waiter 是 top，pi_list_entry 已被 plist_del，符合源码分析）
- **dmesg 异常计数 = 0，设备无重启（uptime 52943s）**——触发是"静默"的，符合预期

## 5. 下一步：P2.4 利用原语工程

### 悬空指针的消费点（源码已确认）

```
T 阻塞在 A 持有的 PI mutex 上
→ task_blocks_on_rt_mutex: if (owner->pi_blocked_on) chain_walk=1   ← A->pi_blocked_on 非空
→ rt_mutex_adjust_prio_chain(task=A, ...): waiter = A->pi_blocked_on   ← 悬空读
→ lock = waiter->lock → raw_spin_trylock(&lock->wait_lock)             ← 受控指针解引用
```

### 路线（按 GhostLock 公开方法论移植）

1. **栈重塑**：A 触发后调用 `pselect(nfds=320)`，fd_set 3×40 字节覆盖到栈上悬空地址；需要计算 `rt_waiter` 在 `futex_wait_requeue_pi` 栈帧中的位置与 `core_sys_select` fd_set 缓冲区的相对偏移（"shift ≤ 3 qwords" 判定）。工具：capstone（pip 安装）反汇编 `futex_wait_requeue_pi`(0xc0...) 与 `core_sys_select`。
2. **伪造 waiter**：控制 `lock` 指针(+0x2c，字偏移 11) → 目标为可写内核地址（倾向 `modprobe_path`/`selinux_enforcing` 邻近结构或 cred 指针链）。
3. **消费**：A 先 `LOCK_PI(m)`，T 再 `LOCK_PI(m)` 阻塞 → 触发链走 → 受控解引用。
4. **提权末端**：`commit_creds(prepare_kernel_cred(0))`（0xc005af14 / 0xc005b570）→ sid=1 kernel 域（unconfineddomain）；持久化问题按用户要求暂缓。

### 关键常量（已备）

- `rt_mutex_waiter`: list_entry@0x00, pi_list_entry@0x14, task@0x28, **lock@0x2c（=字 11，与公开项目常量一致）**
- `struct cred`: security@0x5c；`init_cred`=0xc0b9f1dc；`init_cred.security`→sid=1
- SELinux：`policydb`=0xc0c4eeec（permissive_map 位=类型值）；shell type=1178；kernel type=210
