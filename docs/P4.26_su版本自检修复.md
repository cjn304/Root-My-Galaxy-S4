# P4.26 — "su 二进制可执行文件已过旧" 的真实原因与修复

日期：2026-10-22 04:00–04:30
现象：Amaze 等 app 有时弹提示「su 二进制可执行文件已过旧 / su binary is outdated」

---

## 1. 提示的来源

不是 Amaze。是 **phh Superuser APK 自己的通知**：

```
SuCheckerReceiver（监听 ACTION_BOOT_COMPLETED）
  → SuHelper.checkSu(context)
     → Runtime.getRuntime().exec("su -v")
     → 四项检查，任一失败 → doNotification() → 通知标题 su_binary_outdated
```

`SuCheckerReceiver.java` / `SuHelper.java`（phh 仓库源码，已存 `su_src/SuHelper.java`）：

```java
public static String CURRENT_VERSION = "17";
public static void checkSu(Context context) throws Exception {
    Process p = Runtime.getRuntime().exec("su -v");
    String result = Settings.readToEnd(p.getInputStream());
    if (0 != p.waitFor())                      throw new Exception("non zero result");
    if (result == null)                        throw new Exception("no data");
    if (!result.contains(context.getPackageName())) throw new Exception("unknown su");
    String[] parts = result.split(" ");
    if (!CURRENT_VERSION.equals(parts[0]))     throw new Exception("binary is old");
}
```

所以 `su -v` 必须满足：

| # | 要求 |
|---|---|
| ① | 退出码 0 |
| ② | 有输出 |
| ③ | 输出**包含 APK 包名**（`me.phh.superuser`） |
| ④ | 第一个空格分词 == `"17"`（精确相等，不是 >=） |

**"有时候"的原因**：通知被划掉后 `setCheckSuQuietCounter(context, 3)` 会静默 3 次开机，
所以不是每次开机都弹。

## 2. 我们的 su 为什么失败

原来的 `su_fork2` 不认识 `-v`——`argv[1]="v"` 被当成要执行的命令，
`execvp("v")` 失败 → 退出码非 0 → checkSu 抛异常 → 弹通知。

## 3. phh 原版的输出格式

```c
// su.h
#define VERSION_CODE 17
#define VERSION xstr(VERSION_CODE) " " REQUESTOR      // "17 me.phh.superuser"

// su.c 的 getopt 'v' 分支
case 'v':
    printf("%s cm-su subind suinit\n", VERSION);
    exit(EXIT_SUCCESS);
```

即 `su -v` 输出 `17 me.phh.superuser cm-su subind suinit`。

## 4. 修复

`src/su_fork.c` main 开头，在一切提权流程之前：

```c
if (argc == 2 && (strcmp(argv[1], "-v") == 0 ||
                  strcmp(argv[1], "--version") == 0)) {
    printf("17 me.phh.superuser com.koushikdutta.superuser\n");
    return 0;
}
```

两个包名都带上，兼容 `me.phh.superuser`（F-Droid）和 `com.koushikdutta.superuser`
（原版）两种 APK 的 `contains(packageName)` 检查；首词仍是 `17`。

纯查询，不提权、不写 /dev/ktool、不弹窗，任何调用方都能跑。

## 5. 实测

```
$ su -v
17 me.phh.superuser com.koushikdutta.superuser
su_v_rc=0
```

开机后 logcat（`SuCheckerReceiver` 的 BOOT_COMPLETED 自检）：

```
I/ActivityManager: Start proc me.phh.superuser for broadcast .../SuCheckerReceiver
I/Superuser: Result: 17 me.phh.superuser com.koushikdutta.superuser
```

无异常 → **不再弹通知**。

## 6. 备注

- 该通知纯属提示，不影响提权功能；修复只是让整套东西"看起来是正规的 su"。
- 如果以后换用 koush 原版 APK（`com.koushikdutta.superuser`），同样的输出也能过。
- `su -v` 走的是 `argc == 2` 且参数精确匹配，不会和 `su -v <cmd>` 之类冲突
  （不支持的用法会落到正常流程）。
