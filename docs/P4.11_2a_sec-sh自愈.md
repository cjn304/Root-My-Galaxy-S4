# P4.11 — 2a `sec-sh` 开机自愈实测

日期：2026-10-19
设备：GT-I9500 / I9500ZSSHQD1 / 内核 3.4.5-6264821
目标：不碰 `boot.img`、不烧 Knox，实现"重启后自动把内核补丁与 permissive_map 就位"

---

## 1. 结论

**2a 成立。** `sec-sh` 以 `uid=0` + `u:r:init_shell:s0` 运行，`init_shell` 域内
`writev` 越界、`madvise` 竞态、`sendmmsg` 喷雾全部可用，任意内核读写跑通。

开机自动完成：

| 动作 | 结果 |
|---|---|
| `ktool permissive` | `permissive_rc=0`，伪造 `policydb.permissive_map` |
| `w32 c0012164 0xea000047` | `patch_rc=0`，`sys_execve` KNOX 分支改为无条件跳转 |
| `warranty_bit` | **0** |
| TIMA | `TIMA trustlet: warranty okay d`，无 violation |

重启后执行 `ktool sh`，输出 **`exec patch already on`** —— 补丁由开机脚本打上，
不是本次 `ktool sh` 打的，这是 2a 生效的决定性证据。

---

## 2. 载体

`init.rc:939`（ramdisk 内，**未改动**）：

```
service sec-sh /system/bin/sh /system/etc/init.sec.boot.sh
    class main
    user root
    oneshot
```

- `sec-sh` 是 service 名，不是文件；实体是 `/system/bin/sh` + `/system/etc/init.sec.boot.sh`
- `class_start main` 由 `on nonencrypted`（L675/676）与
  `on property:vold.decrypt=trigger_restart_framework`（L707/708）触发
- 两个触发点都在 `/data` 解密挂载之后，所以 `/data` 下的东西可用

## 3. 实际改动（一次性，写 `/system`）

```
/system/bin/ktool                     1,413,392 B  755  u:object_r:system_file:s0
/system/etc/init.sec.boot.sh          388 → 716 B        u:object_r:system_file:s0
```

脚本末尾追加：

```sh
# ---- 2a auto begin ----
{
  echo "=== 2a auto start ==="
  id
  printf 'ATTR=%s\n' "$(cat /proc/self/attr/current)"
  /system/bin/ktool permissive
  echo "permissive_rc=$?"
  /system/bin/ktool w32 c0012164 0xea000047
  echo "patch_rc=$?"
  echo "=== 2a auto end ==="
} > /data/system/2a_auto.log 2>&1
# ---- 2a auto end ----
```

原脚本备份：`/data/local/tmp/init.sec.boot.sh.orig`
sha256 `bdd62004bbcbc237566898fa6c00d435603e3e9077ba081425464b6b4a147528`

## 5. 踩到的坑

**`ktool patch` 在 2a 场景不可用。**

`do_root()` 里有一道硬编码校验：

```c
if (v != 0x7d0) { printf("cred check FAIL +%x=%x\n", ...); return -1; }
```

`0x7d0 = 2000`，是 adb shell 的 uid，用来防误改。但 `sec-sh` 本身已是 `uid 0`，
校验直接失败：

```
cred check FAIL +4=0
patch_rc=3
```

绕过方式：改用 `ktool w32 c0012164 0xea000047`，它不经过 `do_root`，直接走
`kread/kwrite`，在 `init_shell`（uid 0 + 14 caps）下可用。

**其他小问题**：Android 5.0 的 mksh 没有 `printf`，脚本里那行报
`printf: not found`，不影响功能，可删。

## 6. 副作用与限制

| 项 | 状态 |
|---|---|
| Knox Warranty Bit | 0，未变 |
| TIMA | 无 violation，`warranty okay` |
| System Status | 可能变 Custom（改过 `/system`），可刷回官方 system.img 恢复 |
| 开机耗时 | 多跑两次 exploit（`permissive` + `w32`），未精确测量 |
| `permissive_map` | 开机即生效，全局 permissive；TIMA 本轮未告警 |
| root 常驻 | **没有**。`ktool sh` 仍需手动跑一次拿 cred |

**2a 的边界**：它只让"内核补丁 + permissive"开机自动就位，不等于"开机即有 root
shell"。真正的常驻需要守护进程 + IPC（2b）。
