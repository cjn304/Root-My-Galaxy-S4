# P4.10 结案：`0x1ec` 的矛盾不存在，是补丁状态污染了观测

**时间**：2026-10-19 19:40
**结论**：之前所有「父子进程版能绕过 KNOX」的成功，**全部是 `sys_execve` 补丁残留造成的**。撤掉补丁，父子版 3/3 全败。

---

## 1. 决定性实验

```bash
ktool unpatch                      # c0012164: 0xea000047 -> 0x0a000002
ktool dump c0012164 8              # 0200000a  ← 恢复原值

ktoolx sh -c id   × 3              # 父子版
→ /system/bin/sh: id: Permission denied
→ /system/bin/sh: id: Permission denied
→ /system/bin/sh: id: Permission denied
```

打回补丁后：

```bash
ktool patch                        # 0a000002 -> ea000047
ktool sh -c id
→ uid=0(root) gid=0(root) ...
```

**同一个二进制、同一条命令、同一个 cwd，唯一变量是 `c0012164` 那 4 个字节。**

---

## 2. 时间线还原

| 时间 | 观测 | 真实原因 |
|---|---|---|
| 19:04–19:06 | ktool3（父子版）`id; ...` **4/4 成功** | 当时补丁已打（之前某轮 `ktool sh` 留下的） |
| 19:15 | ktoolc / ktooln 全失败 | 补丁已被撤销 |
| 19:21 | 恢复补丁版，`ktool sh` 重新打补丁 | `c0012164 = 0xea000047` |
| 19:28–19:35 | ktoolx（父子版）**5/5 成功** | 补丁在 |
| 19:39 | `ktool unpatch` → 父子版 **3/3 失败** | 补丁不在 |

**「方案不稳定」是个假象。真实情况是：父子版从来就无效，成功全部来自补丁。**

---

## 3. 那个「矛盾」也一并消失

之前记录的现象：

- `sh` 自己 exec `id` 被拦
- `sh` fork 子进程 exec `cat` 放行
- 两者 `mm->exe_file` 都是 `/system/bin/sh`

**现在看：这些观测发生在不同时间点，补丁状态不同，所以结果不同。** 不是 fork/exec 的差异，是补丁的有无。

**P4.8 里「同一个 exe 判定不同」的矛盾，不成立。**

---

## 4. 路径链的额外发现（这个是真的）

手动从 `exe_file->f_path.dentry` 逐层读 `d_parent` / `d_name`：

```
[path] 0 dentry=e502b908 name=sh   parent=e66e2f68
[path] 1 dentry=e66e2f68 name=bin  parent=e66e2bb0
[path] 2 dentry=e66e2bb0 name=/    parent=e66e2bb0
```

`dentry` 链到 `/system` 的挂载根就停了（`d_name` 是 `/`），**不含 `system` 这一层**——因为 `/system` 是独立挂载点，`d_path` 靠 `mnt` 补前缀。

**这印证了 `d_path` 的语义：返回的是「相对于 `current->fs->root`、到 `mnt_root` 为止」的路径，再拼挂载点。** 这也说明 `d_path` 的结果确实可能受 `fs->root` 影响——但这一层在补丁存在时根本不执行。

---

## 5. 教训

这次连续几轮判断失误，根因只有一个：**没有把「内核补丁状态」当作实验的控制变量。**

具体表现：

1. P4.7 说「chdir 是必要条件，4/4 成功」→ 其实是补丁在
2. P4.8 说「方案不稳定，时好时坏」→ 其实是补丁时有时无
3. P4.8 花了大量篇幅追一个「矛盾」→ 矛盾是伪命题

**以后任何 exec 相关实验，第一步都应该先 `ktool dump c0012164 8` 记录补丁状态，并写进结果里。**

---

## 6. 最终结论

| 方案 | 有效性 |
|---|---|
| **`sys_execve` 4 字节补丁** | **唯一有效**，多轮复现 |
| 父子进程 + ptrace + chdir | **无效**，之前成功全是补丁残留 |
| 模块 | 死（哈希校验） |
| `ktool ls / cat / cp` | 有效（不 exec，绕过检查） |

**`0x1ec` 的静态分析部分仍然成立**（它是 `mm`，`get_mm_exe_file` 读 `mm+0x188`，`d_path` 拼路径），但「fork 与 exec 判定不同」这个现象不存在，不需要再追。

**当前设备状态**：补丁已恢复（`c0012164 = 0xea000047`），`ktool sh` 可用。用完 `ktool unpatch` 或重启即撤销。
