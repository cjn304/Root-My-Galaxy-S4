## 二、setsid：根因不是「写不进去」，是「写完读不回来」

### 现象

第一次调用成功，之后连续 30 次报 `sid write failed`（`kwrite_verify` 每轮
`kwrite` + `kread` + `memcmp` 全部没匹配上）。

### 根因

`sid` 就是本进程的 SELinux 域。写进去的那一瞬间域就换了，**后续操作全部在新域下执行**。
iovyroot 的 pipe/iovec 原语在新域下的表现和旧域不同（pipe 创建、writev、madvise
这一串的系统调用入口在新域下走了不同的判定路径），于是：

```
第 1 轮  kwrite 成功（此时还是旧域）  → kread 已经在 新域   → 失败
第 2 轮  kwrite 已经在新域             → 失败/不落地       → 失败
...
第 30 轮 同上
```

`kwrite_verify` 把「读回失败」和「写失败」当成同一件事，所以报的是**假警报**。

反证：P4.93 记录当时靠 `setsid init_shell mount -o rw,remount /system` 破的局。
`mount` 是 exec 出去的新进程，如果 sid 没写进去，它还是旧域，AVC 缓存里那条
`remount` 的旧 deny 会继续拒绝 —— 而它成功了。所以写入确实落地了。

### 修复

不再校验，只写一次：

```c
if (kwrite(sec, pair, 8) != 0) { ... return 3; }
fprintf(stderr, "setsid: sid -> %u written (unverified)\n", sid);
```

域到底改没改，唯一可靠的外部证据是 **exec 之后看 `/proc/self/attr/current`**，
不依赖任何内核内存读：

```
ktool setsid init_shell sh -c 'cat /proc/self/attr/current'
```

顺带：`setsid` 只改当前进程，进程一退 sid 就没了；原来不给 cmd 也返回 0，
容易被误当成「改完了」。现在不给 cmd 会明确告警。

## 三、sud 目录 0777：剩下的只是可用性 DoS

已有的两道锁：

| 位置 | 作用 |
|---|---|
| `su_fork.c:308` `unlink(sock_path)` | pid 复用不会 bind 失败 |
| `su_fork.c:338` `SO_PEERCRED == admin_uid` | 别的 app 连上来直接丢弃，最多丢 3 次 |

所以**提权路径已经堵死**（早先「任意 app 发 ALLOW 就放行」那个洞是 PEERCRED 补的）。
剩下的问题只是：任意 app 可以在 0777 目录里抢先 `unlink` 掉我们的 socket 文件，
或抢先 bind 同名路径，导致这次弹窗失败 —— 是 DoS，不是提权。

要收的话，两步都不碰 APK：

1. 目录改 `01777`（sticky，别人删不掉你的文件）
2. socket 文件名从 `s<pid>` 改成 `s<pid>_<rand>`（`/data/local/tmp/sud` 的路径
   本来就通过 `am start --es socket <path>` 传给 APK，APK 自己不算路径）

代价：`unlink` 在 01777 下只能删自己 uid 的文件，跨 uid 复用 pid 时 bind 还是可能失败 ——
但那种情况本来就该失败（说明 pid 号被别人占着）。

## 四、REPL 历史：落盘，不用 atexit

```
#define KT_HIST_FILE "/data/local/tmp/.ktool_hist"
```

- 每次 `kt_hist_add` 追加一行 → exec（`root`/`sh`/`x` 都会 exec）也不丢
- 启动时读回，只保留最后 16 条进环
- 写失败（在 `init_shell` 域对 `shell_data_file` 没有 write）就静默降级为纯内存

## 五、两条被划掉的

**`avrule_enable=0`**：模块参数描述写的是 `1=apply su avtab rules at init (default),
0=skip`。关掉开关就等于没做策略手术，应用侧当然退回依赖 permissive —— 这是开关的
**定义**，不是在 `avrule_enable=0` 下还有什么隐藏 bug。开机脚本记录 `avrule_applied=1`，
默认路径没问题。

**D 状态进程**：全仓库 grep 不到任何写 `/sys/fs/selinux/load` 的调用
（`kmod/ktool_mod.c:521`、`src/ktool.c:1581` 都只是注释在解释**为什么不做**）。
设备实测 `ps -A -o PID,STAT` 没有任何 D 行。这条是历史上做策略加载实验留下的，
只要不再写 selinuxfs 就不会再生。
