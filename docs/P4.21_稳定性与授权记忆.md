## 3. 自动化点按钮踩的两个坑

**坑一：唤醒 ≠ 解锁。**

`input keyevent 224` 只是点亮屏幕，Activity 仍被锁屏盖着，`uiautomator dump` 抓不到。
必须补一条滑动：

```sh
input keyevent 224
input swipe 360 800 360 100 300
```

**坑二：不要 blind tap。**

先 `sleep 5` 再盲点坐标，会因为 APK 冷启动慢而落空，UI 在 30 秒倒计时后自动 deny，
表现为 `su: denied (uid ..., DENY)`，看起来像协议 bug，实际是没点到。

正确做法是轮询：

```sh
i=0
while [ $i -lt 12 ]; do
  uiautomator dump /data/local/tmp/u.xml >/dev/null 2>&1
  if grep -q id/allow /data/local/tmp/u.xml; then break; fi
  i=$((i+1)); sleep 2
done
```

实测第一次轮询（`UI_AT_0`）就抓到了。

## 4. 「Superuser 请求 Superuser 授权」是怎么回事

测试时用 `ktool setuid 10198` 把调用 su 的进程 uid 伪装成 10198，
而 10198 正是 `me.phh.superuser` 自己的 uid。APK 的授权界面按
**uid → 包名** 反查调用方，于是显示成「Superuser 请求超级用户权限」。

**不是 APK 在请求自己，是 adb 伪装的。** 真实 app 调 su 时，弹窗显示的是那个 app 的名字和图标。

顺带说明：这一条正是现成 APK 的价值——按 uid 反查包名、显示图标、三档授权
（仅此一次 / 记住 N 分钟 / 永久），自己写一套要花不少时间。
