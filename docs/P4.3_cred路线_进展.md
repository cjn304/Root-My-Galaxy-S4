# P4.3 cred 路线：进展与卡点

**时间**：2026-10-18 22:0x
**结论**：结构偏移已确认，读工具单次可靠；但同一进程内跨地址连续读会读到错误数据，cred 修补尚未完成。

## 1. 已确认的结构偏移（设备实测 + 代码反推）

| 字段 | 偏移 | 依据 |
|---|---|---|
| `task_struct.tasks` | **0x1d0** | `show_state_filter @0xc0064340`：`ldr r3,[r6,#0x1d0]` / `sub r6,r6,#0x1d0` |
| `task_struct.thread_group` | 0x27c | 同函数内层循环 |
| `task_struct.real_cred` | 0x2f8 | init_task 里读到 `&init_cred (0xc0b9f1dc)` |
| `task_struct.cred` | **0x2fc** | 同上 |
| `task_struct.comm` | **0x304** | init_task 里读到 "swapper/0"；`init`/`kworker/2:0` 交叉验证 |

链表遍历已跑通（从 `init_task.tasks.next` 依次读到 init → kthreadd → ksoftirqd/0 → …），
说明偏移全对。

## 2. 卡点：同一进程内多地址连续读会读到错数据

- `ktool dump e68481c0 64`（单次读）→ 正确：第 4 个字 `e6848610` = kthreadd.tasks
- `ktool find ktool`（先读 comm 再读 tasks）→ 同一地址读出 0

已排除：
- 不是地址算错（dump 用同一地址是对的）
- 不是 nonce 误判（4 次连读结果一致但值错）
- 加 4 次喷洒 + `usleep(50)` 只能让结果"稳定地错"

怀疑方向：`sendmmsg` 的 skb 在 softirq 里延迟释放，把 `kmalloc-4096` freelist 头换成了非我们喷的对象；
单次读时窗口小所以命中，连续读时被插队。

## 3. 下一步（二选一）

A. **修读原语**：把喷洒从 `sendmmsg` 换成 `msgsnd/msgrcv`（SysV 消息，kmalloc(0x30+4048) 同步释放），
   或每次读取前重建管道 + 多次喷洒 + 校验重试。
B. **绕开连续读**：每个读一个进程（`ktool dump <addr> 64`），用 shell 驱动链表遍历。
   代价是 ~200 次进程启动（每次要重新拉 CPU 上线），慢但确定能跑通。
