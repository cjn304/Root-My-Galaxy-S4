## 2. 内核配置确认（ja3g_00_defconfig）

- `CONFIG_FUTEX=y`、`CONFIG_RT_MUTEXES=y` — 漏洞编译路径激活
- `CONFIG_IKCONFIG` 未设 — 与 kernel.raw 中无 IKCFG_ST 魔数自洽
- `CONFIG_KALLSYMS=y` — 内嵌符号表（见 §4）
- `CONFIG_DEVMEM=y` 且 `CONFIG_STRICT_DEVMEM` 未设 — /dev/mem 无内核级限制（受 SELinux 约束）
- `CONFIG_GENERIC_LOCKBREAK=y` — raw_spinlock_t = 8 字节（偏移推算关键输入）
- `CONFIG_SMP=y`、`CONFIG_PREEMPT=y` — 与 banner `#1 SMP PREEMPT` 一致
- banner：`Linux version 3.4.5-6264821 (dpi@SWDG2906) gcc 4.8 ... 2017-04-01 KST`，与 boot.img 文件日期（2017-04-01）吻合

## 3. 漏洞触发链（源码行号级映射）

```
线程B: futex(FUTEX_CMP_REQUEUE_PI)
  → kernel/futex.c L1358 futex_requeue(..., requeue_pi=1)
  → L1549 rt_mutex_start_proxy_lock(&pi_state->pi_mutex, this->rt_waiter, this->task, 1)
      // waiter 属于线程A（睡在 uaddr1 上），current 是线程B
  → kernel/rtmutex.c L966 task_blocks_on_rt_mutex(lock, waiter, task, ...)
  → 失败（如 -EDEADLK）时 L974 remove_waiter(lock, waiter)
      // remove_waiter 内部操作 current(B)：L498 current->pi_lock、
      // L500 current->pi_blocked_on = NULL、L536 chain walk 传 current
      // → A 的 PI 状态未清理，B 的 pi_blocked_on 被错误置空
```

上游修复 = `remove_waiter()` 内 `current` → `waiter->task`。本地三处调用点中仅 L974（start_proxy_lock）语义错误；L653（slowlock）、L1035（finish_proxy_lock）的 current 语义正确。

## 6. ramdisk 情报（GT-I9500ZSSHQD1 boot.img）

### default.prop（关键三项全封死）

```
ro.secure=1
ro.debuggable=0
ro.adb.secure=1
```

→ adbd 以非特权 shell 运行；`init.rc` 中 `adbd --root_seclabel=u:r:su:s0` 需 ro.secure=0/ro.debuggable=1 才激活 → **adbd root 路径死**。

### sepolicy（399,655 字节）

- 头部：magic 0xf97cff8c ✓，policydb version **26**（偏移 0x10），config=1（MLS 开），SYM_NUM=8，OCON_NUM=7
- 域字符串精确匹配：`shell`✓ `adbd`✓ `untrusted_app`✓ `init`✓ `zygote`✓ `runas`✓ `debuggerd`✓ —— **`su` 不存在（count=0）**
- `su_exec` 文件类型存在；file_contexts L152：`/system/xbin/su → u:object_r:su_exec:s0`

**→ shell→su 域转换没有目标域，此路不通（文档 §56 行悬而未决的问题已有答案）。**

### 推论：唯一提权后路径

内核态执行 `commit_creds(prepare_kernel_cred(0))`：
- uid/gid/caps → init_cred（全 0 uid + 全 capability）
- cred->security → 复制 init_cred 的 security blob（kernel sid）→ SELinux Enforcing 下按 kernel 主体检查（Lollipop 时代三星设备各公开 exploit 的标准做法，本机策略的具体 allow 范围待深度解析确认）

## 关键问题答案

### 1. su 域

- `su` 进程域**不存在**（字符串精确匹配 0 次）
- `su_exec` 仅 4 条 allow：diagandroid_app / system / debuggerd / at_distributor 可 `execute`
- **不存在任何 type_transition 指向 su 域**
- 结论：init.rc 的 `adbd --root_seclabel=u:r:su:s0` 是死配置；**文档 §56 行"shell→su 转换权限"悬念关闭：无目标域，此路不存在**

### 2. setenforce 三层封死（实测证据）

| 层 | 证据 | 结论 |
|---|---|---|
| 写路径 | `selinuxfs.c:169-181`：`#ifdef CONFIG_ALWAYS_ENFORCE` 下 `new_value = 1` 硬编码 | setenforce 写不进去 |
| AVC 判定 | `avc.c:1081-1086`：`ALWAYS_ENFORCE` 下拒绝条件为 `!(flags & AVD_FLAGS_PERMISSIVE)`，**完全无视 selinux_enforcing 变量** | 即使内核态改 `selinux_enforcing=0`（0xc0c4d490）也**不放行** |
| 启动/禁用 | `CONFIG_SECURITY_SELINUX_BOOTPARAM`、`SELINUX_DISABLE` 均未设 | cmdline/运行时禁用不可用 |

二进制旁证：`config_always_enforce - true` 字符串存在于 kernel.raw（仅 `#ifdef` 内编译），
`CONFIG_SECURITY_SELINUX_DEVELOP=y`（enforce 文件存在但写无效）。

**唯一豁免通道：per-domain permissive 标志（`AVD_FLAGS_PERMISSIVE`）。**

### 3. kernel 域（sid=1）能力全景

- 属性成员：`unconfineddomain`、`mlstrustedsubject`、`mlstrustedobject`、`domain`、`cts_domain`
- **capability：全部 26 项**（dac_override, sys_admin, sys_module, mknod, setpcap, sys_rawio 未列但 mknod/sys_module 在）
- process：ptrace, setcurrent, setexec, setfscreate, setsockcreate, setkeycreate, sigkill, fork... 全权
- file：对 `dev_type`/`exec_type`/`contextmount_type` 等 **全权限集**（含 write/relabelto/mounton/swapon/execmod）
- blk_file：`device`/`block_device`/`emmcblk_device`/`ram_device`/`loop_device` 全 RW
- filesystem：labeledfs mount/unmount、usbfs mount
- security：`check_context`/`compute_av`/`read_policy`/`setcheckreqprot`
- **process transition：`kernel shell_exec → shell`（exec sh 会掉回 shell 域，必须在 exec 前完成特权操作或改 permissive）**

### 4. init_cred → sid 实证

二进制直读：`init_cred(0xc0b9f1dc).security = 0xc0b9e964` → `task_security_struct{osid=2, sid=1, ...}`
→ `commit_creds(prepare_kernel_cred(0))` 后当前进程 SID = 1 = **kernel 域（unconfineddomain）**。

### 5. shell 域边界（对照）

- capability：**无**
- selinuxfs/debugfs：`append,write`（但 setenforce 被 §2 挡死）
- 可写：cache_file、sdcard、shell_data_file、media_rw、sysfs_app_writable、cgroup、anr_data_file 等
- 不可写：system_file/exec_type
- transitions：`runas_exec→runas`、`dumpstate_exec→dumpstate`、`bugreport_exec→bugreport`、`dumpsys_exec→dumpsys`、`tima_dump_exec→system`

## 对 P2 的实施含义（设计结论）

1. 提权后**不要 exec**：exec 把域带回 shell；特权操作（写文件、mount、改权限）必须在 kernel 域窗口内完成。
2. 若需要持久可用的 root shell，必须让 shell 域变 permissive 或改策略内存结构（`permissive_map` / sidtab 标志），
   或在内核态直接修改目标对象——**这是 P2 的核心技术选型点**。
3. `selinux_enforcing=0` 方案作废（§2，AVC 不看该变量）。
4. 全部 0 permissive 域 → 不能依赖现成宽松域。
