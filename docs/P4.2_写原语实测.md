# P4.2 写原语实测：任意内核写成立

**时间**：2026-10-18
**结论**：**`pipe_read` 方向的任意内核写已实测成功。** 但 `selinux_enforcing` 被写 0 后
MAC 仍然生效（`CONFIG_ALWAYS_ENFORCE`），这条路只改了个显示值。

---

## 1. 写原语自检（用户 canary，零风险）

```
[*] write primitive test, max_iter=3000 target=user b5f6e000
    it=0 readv=8192 canary=ccccccccdeadbeef cccccccccccccccc
[+] WROTE it=0 canary=ccccccccdeadbeef cccccccccccccccc
```

管道第二个 buffer 的尾部构造成 `4 字节 0xDEADBEEF + 12 字节 0xCC`，
OOB 项 `iov[257]={canary+0,4}`、`iov[258]={canary+4,12}` →
目标地址收到的正是这 16 字节。**第一轮即命中。**

机制与读方向同源，只是把 `pipe_write` 换成 `pipe_read`：
`__copy_to_user_std` 的 `iov_base` 变成写入目标，atomic 趟（`kmap_atomic`）没有 `access_ok`。

竞态也完全复用同一个 zapper（`madvise(MADV_DONTNEED)`）：
`pipe_read` 的预取是内联 `strb` 写 0（`c0105728`），会先把 pR 缺页进来；
zapper 在「预取之后、copy 之前」清 PTE → copy 在 `in_atomic` 下缺页 → EFAULT；
重试走可睡眠 `kmap`，VMA 还在 → 必然重新缺页成功。

## 2. 内核写实测

```
before=1
[*] write primitive test, max_iter=1000 target=kernel c0c4d490
[*] done canary=0000000000000000 0000000000000000
after=0
up time: 00:01:50     ← 没有重启
```

`selinux_enforcing @0xc0c4d490` 从 1 变成 0，`getenforce` 报 `Permissive`。
**任意内核写成立。**

## 3. 但 permissive 是假的（CONFIG_ALWAYS_ENFORCE）

```
$ ls -l /sys/fs/selinux/policy        → -r--r--r-- root root   （DAC 允许所有人读）
$ cat /sys/fs/selinux/policy          → Permission denied      （MAC 仍然拒绝）
```

`avc_has_perm_flags @0xc02018b4` / `avc_denied.isra.1 @0xc06f4538` 里
**没有对 `selinux_enforcing` 的任何引用**（`movw/movt` 也没有）。
全镜像里该地址只出现在 kallsyms 地址表（`0xc0883e1c`）里。
→ AVC 里这个变量已被编译期折叠成常量 1，只有 sysfs 的 `enforce` 属性还在读它。

**结论：写 `selinux_enforcing` 只能骗 `getenforce`，不能关 MAC。**
RAM 里的改动重启即消失，设备无残留。

## 4. 一次事故（已修复）

第一次内核写测试时把 OOB 第二项也指到了 `target+4`，结果往 `0xc0c4d494` 写了 12 字节 `0xCC`：

```
c0c4d490  selinux_enforcing   ← 目标
c0c4d494  default_noexec
c0c4d498  sel_inode_cache     ← 被 0xCCCCCCCC 覆盖的 kmem_cache 指针
```

设备在程序退出后 panic 重启（uptime 归零，SELinux 回到 Enforcing）。
**没有烧 Knox、没有变砖**，只是普通重启。
修正：OOB 第二项固定指向用户态 canary，内核目标只写 4 字节。

## 5. 下一步：cred 而不是 selinux_enforcing

现在有任意读写，路线是：

1. 读 `init_task @0xc0b79be0`，在头 0x600 字节里找 `tasks` 链表头
   （特征：`next`/`prev` 都是内核地址，且 `next->prev == &init_task.tasks`）
2. 沿链表走，读每个 task 的 `pid`/`comm`，找到自己（pid = getpid()）
3. 读 `task->cred`，再读 `cred->security`（`task_security_struct {u32 osid; u32 sid;}`）
4. 写 `cred->uid/gid/euid/...` = 0，写 `security->sid` = 1（kernel SID）
5. 之后再 `setuid(0)` / 起 root shell

offset 不靠猜：每一步都先用读原语打印出来核对（pid/comm 就是最好的校验）。
